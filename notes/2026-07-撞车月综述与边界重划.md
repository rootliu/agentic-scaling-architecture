## 一、格局判断

7 月这批工作共同确认了一件事：**"harness 是可扩展性与可管理性的关键层"已经成为共识议题，不再是本文独有的洞察**。因此本文的价值必须从"提出这个层"转移到"**给出这个层的双轴分离条件与可证伪协议**"。

## 二、最危险的一篇：Falsifiable Release Gates

`2607.13070`（Deepak Soni，单作者）几乎是本文架构的**实现版**：

- "capability token issued by control ring before effector" ≈ 本文**完全中介 + typed closure**
- 预先声明的机器可检查验收套件 ≈ 本文**确定性 gate**
- TLA+ 有界模型检查、跨 6 个 release 不变量一字未改 ≈ 本文**可证伪协议**
- **且有实测**：治理开销 0.021 ms/请求（占推理成本 0.008%）

### 它直接反驳了本文的一个推测

本文 §10.1 原写"契约编译延迟约 low tens of milliseconds"——与实测 **0.021ms 差三个数量级**。这是本次审查中最实质的一处错误。

**v9 处理**：§10.1 删除自造估计，改引其实测值作为**下界**（其只覆盖不变量求值，不含 schema 校验 / 图构造 / 绑定解析），并明确该量交由 Protocol 9.6 测量；真正的问题改为"加入 schema 与绑定工作后是否仍在同一数量级"。

### 剩余边界

其范围是**单个 runtime 的安全核 + 有界模型**，不把逻辑能力增长与物理吞吐增长当作可分别扩展的两轴；其不变量治理 **action-to-effector** 路径，而非 **capability-to-capacity** 绑定。这是 v9 §4 明确写入的边界。

## 三、P15（双子目标 Reward）的边界重划

三篇平行工作出现：

- **GSME (2607.13683)**：LLM 只做诊断，采样/测量/显著性检验全归确定性代码；补丁按 `(WHERE × WHY) pathology` 归档。sealed test +9~15.5pp。
- **WML (2607.20999)**：Node–Mechanism Attribution 定位失败节点 + 涉事机制 + 最小有效编辑目标。SpreadsheetBench hard 90.33±1.53。
- **Do Agent Optimizers Compound (2607.14004)**：**这篇支持本文**——增益只在 regression control 内置于优化环时复合（RELAI-VCL 76.4% vs GEPA 66.0%，GEPA 甚至跌破 baseline 58.7%）。

### 真正的区别（v9 §8.5 新增段落）

前两篇都按**事后推断（discovered after the fact）的失败属性**索引 credit；本文按**契约先验声明的 σ_out 子域**索引。实际后果有二：

1. reward 维度由 Harness 已在 gate 的同一份声明固定，不需要额外的诊断步骤；
2. 与 §7.4 的运行期 satisfaction ratio **共用同一结构**——训练期归因与运行期完备性同构。

并明确声明"契约维度是否优于诊断维度"是**开放问题**，不是本文主张。这比原先"双维比 scalar 更好"的表述要窄得多，但站得住。

## 四、协议层加固（4 处）

| 来源 | 发现 | v9 修改 |
|---|---|---|
| Progressive Disclosure (2607.17598) | 渐进披露收益在**强 harness 下趋零**，仅在语料库规模决定性；第二层路由从不帮忙 | §9.1 Control：固定并报告 harness 检索能力；单源/多源双规模测；激活深度固定一层 |
| Long Contexts (2607.17937) | requirement coverage **>92% 而结果崩塌**（8/10→3/10）；外部 checklist 10/10 vs 自检 5/10 (p=0.0325) | §9.1 Metrics：新增"每条需求全满足的运行占比"，并记录具体被丢弃的需求 |
| AEVAL (2607.16345) | 自修复自评把通过率灌水成**虚假 100%** | §9.7/§9.8 Control：executor/grader 分离 + first-attempt grading + self-correction 单独计数 |
| Phantom Guardrails (2607.13083) | 自改进 harness 为**从未发生的失败**捏造 guardrail：60 次中 15 次（对照 0/60） | §8.5 判据须为登记产物；§9.8 新增 oracle 校验证伪条件 |

Phantom Guardrails 那条是**送给本文的一条新证伪条件**：因为 r_proc 依赖"step 是否满足判据"的判定，若判据由模型在评分时生成，则带维度标注的负反馈本身可能是虚构的。因此 v9 规定判据必须是**运行前登记的固定产物**，并在 §9.8 加入用 byte-exact oracle 校验每条 rejection reason 的证伪条件——**即便收敛更快，若理由含虚构违规则"归因更清晰"主张失效**。

## 五、本次同时写入论文的新内容

除上述边界重划外，v9 还把用户口述的 harness 强度设计正式写入 **§7.4 Derivation-Closure Orchestration + Figure 4**：

- 子 agent 持有**相对固定的 tool-set / data-set**，从而界定其**输出范围**（高内聚的可操作读法：不是 prompt 聚焦，而是契约在一对集合上闭合）
- 对集合外工具/数据源的引用**不就地授予**，而是成为**派生下一个子 agent 的准入条件**（因此单个请求内的能力增长靠"加有界子 agent"而非"扩大既有 agent"）
- 主 agent **不执行任务工具**，只做 summarize + semantic join + top-k，并按声明的 σ_out 子域计算 **satisfaction ratio**；低于目标且仍有未满足子域可派生时继续循环，否则终止（无候选时是**typed failure**而非降级答案）

三个由此得到的性质：终止判据是**契约级谓词**而非模型判断；跑过的子 agent 集合是"请求真正需要哪些能力"的**完整记录**；per-sub-domain 结构让运行期完备性与训练期 reward **同构**。
