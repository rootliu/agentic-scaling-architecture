# 评审：v21《Enterprise Architecture》× v22《Separability Study》拆分两篇

- **评审对象**：`~/academy/Enterprise_Architecture_v21.pdf`（32 页）与 `~/academy/Separability_Study_v22.pdf`（16 页）
- **对照基线**：上一轮对 v20 的评审意见（见 [[15-v20-论文评审与改进意见]]）
- **总体判断**：拆分方向正确，v22 是实质性升级；但**两篇之间存在硬一致性矛盾**，这是当前最需要先修的问题。

---

## 一、两篇的分工与新内容

**v21（企业架构篇）**：保留 v20 的完整架构叙事——四责任对象、Harness 契约、六条件、P15/P16/P17、AI4Science walkthrough。主要新增：
- Table 3 逐条登记每个 claim 的证据状态（设计提案/解释性论点/命题 + 当前证据等级）；
- §10.2 Artifact and Preregistration Statement（"无实验即无 artifact，可被判的是协议可独立执行性"）；
- §11 明确承认"六条件合取可能贵到 P1 只能在弱化场景下可测，外部效度存疑"；
- 吸收 7 月撞车月文献：§9.1 加入 Progressive Disclosure 的检索能力固定/单层激活深度控制、长上下文失败研究的"全需求满足占比"指标；
- P2–P14 撤回或并入六条件，只留 P15/P16/P17，编号保留以便与旧稿对照（诚实且必要）。

**v22（可分离性研究篇）**：把 P1 单独抽出来做成一篇测量协议论文，核心升级四处：
1. **P1 重述为 cost-aware separability**：能力-容量可分离 + 执行成本不超预算，三方决策（supported / falsified / inconclusive），不再是二元猜想；
2. **六条件变为"测量义务"**：每条义务五个必报输出（instrumentation coverage、observed violations、uncertainty、enforcement cost、Omega exclusions），预设覆盖率下限 γ、违规率上限 ν、监测灵敏度下限 η，未覆盖事件按违规计（保守方向，正确）；
3. **实验设计换成 cluster-period 随机交叉试验**：直接引进临床试验方法学——TOST 等效检验（Schuirmann 1987）、CONSORT 非劣效报告（Piaggio 2012）、交叉试验（Jones & Kenward）、整群交叉分析（Turner 2007）；reset 哨兵给了具体数值界限；完整序列主估计 + 分配级 ITT 敏感性分析 + tipping-point；
4. **Foundations 一节补齐经典谱系**：Parnas 信息隐藏、Anderson 1972 参考监视器、Saltzer-Schroeder、Capability Myths、Hydra 策略/机制分离、SDN 控制/数据面、MAPE-K、ISO 25010、排队论（Kleinrock、Tail at Scale、Bubble-Up）。

## 三、新发现问题（按优先级）

### P0 — 两篇互不引用、同名、且核心实验设计互相矛盾

1. **互不引用、标题相同**。两篇 PDF 标题完全一样（"A Contract-Centered Architecture for Scalable and Manageable Agentic Runtimes"），running head 也相同，正文零交叉引用。读者无法从标题区分，投稿时会被当成重复提交。建议改名：
   - Part I: *…— Enterprise Architecture and Responsibility Contracts*
   - Part II: *…— A Falsifiable Separability Study*
   并在各自引言用一段话互相锚定。

2. **实验设计矛盾（最严重）**。v21 §9.1："The unit of randomization is **one independent run**"；v22 §7.1 明确否定："Requests inside a period are **repeated observations, not independent randomized units**"，单位是 cluster-period。更直接的冲突：v21 §9.1 的处理变量是"向注册表批量添加无关 Skill 测上下文增长"，而 v22 §7.1 明说"**Adding inactive registry entries is not a treatment**"。v22 的交叉设计在方法学上明显更严谨（整群相关、结转效应、洗脱都有处理），**建议以 v22 为准**，v21 §9.1/9.2 瘦身为一个段落 + 指向 Part II；v21 独有的 registry-scale 检索压力测试可作为独立协议保留，但要改写成不与 v22 的处理定义冲突（它测的是 selective activation 机制本身，不是 P1）。

3. **契约元组字母不一致**。v21 用 `C=<I,O,G,B,E,T>`（E=effects，T=identities），v22 用 `C=<I,O,G,A,B,V>`（A=authority/effects，V=versions）。两篇的 Figure 2 字段字母对不上。同一系列内必须统一，任选一套全局替换。

### P1 — v22 统计与测量层的四个具体缺口

4. **六合取 → inconclusive 概率膨胀**。六条义务每条都要独立过 γ/ν/η 三阈值，任一不过则 P1 不可判。论文承认了这一点（"can make useful deployments inconclusive"），但没有给出缓解方案。建议增加**分层报告结构**：即使整体 inconclusive，也逐义务报告支持度等级（fully measured / partially measured / unmeasurable），并预注册一个"5/6 义务通过 + 唯一失败义务的残差耦合剂量-反应分析"是否可降级为 conditional-engineering result 的规则——否则单个难测渠道（如 scheduler independence）会永久锁死整个研究线。

5. **E(c,s) 仿真器测的是门开销，不是执法的全部成本**。§7.3 的配对回放"identical model and tool outputs"意味着 enforcement-on 臂无法捕捉 admission 拒绝对后续规划行为的影响（一次工具拒绝会改变模型后续轨迹，这部分成本/收益被固定输出抹掉了）。建议明确声明：E(c,s) 估计的是**边际运行时执法开销**，被拒行为的机会成本属于 Q(c,s) 语义结局的一部分——否则审稿人会把它当成低估了执法成本。

6. **具体数值界限缺领域论证**。§7.2 的洗脱哨兵（log-p95 在 ±log(1.05) 内、全需求满足风险差 ≥ -0.025）直接给出数字，但 §9 自己要求"margins must be justified in domain terms"。这两个数字目前没有任何论证，与论文自己的标准不一致。

7. **多语义结局的多重性**。§9 提到需要"prespecified decision hierarchy or multiplicity rule"，但没有给出具体方案。哪怕指定一个简单层级（Qreq 为主、其他按预设顺序守门）也比留白强。

### P2 — v21 遗留与编辑项

8. **补 dispute/escalation 一节**：Harness 拒绝/路径否决的申诉通道、契约争议仲裁、误杀 Skill 的恢复流程。这是四责任对象模型在组织侧的最后一块缺口，半节即可。
9. **谱系下沉**：把 v22 §4 的 Foundations（至少 Anderson/Saltzer/Parnas/ISO 25010 四条）以引用形式接入 v21 §6.2 威胁模型与 §5.1 NFR 清单，否则拆开投稿后 v21 显得无根。
10. **去重**：两篇共享的 Figure 1–3、契约解剖、控制/数据面图应各自只留一份，另一篇引用之；拆分后两篇合计 48 页，比 v20 的 27 页膨胀了近一倍，其中约 6–8 页是纯重复。
11. **Goguen & Meseguer 1982** 补进 v22 §4（effect non-interference 条款处）；可选加 Denning 1976 或 Sabelfeld-Myers 2003 锚定信息流语义。
12. **小项**：v21 日期 2026-08-04 / v22 2026-08-05，若作为同期系列应统一；academy 目录下两篇各有同字节数的重名副本（`Enterprise_Architecture_v21.pdf` ≡ `..._v21.pdf`），建议统一命名规则，避免后续引用混乱。

## 四、总体判断

v22 是这条研究线迄今最扎实的一步：把猜想从"架构美德"改造成"带覆盖率、灵敏度、成本预算的测量义务"，并且诚实地把 inconclusive 设为一等结局。方法学上已经达到可投 systems/SE 实验方法类 venue 的形态。**当前最大的风险不再是内容深度，而是拆分后两篇的一致性**：同名、互引缺失、契约字母漂移、尤其是实验单位的直接矛盾，任何一条都会在评审中被抓住。建议的下一步顺序：

1. 改名 + 互引（半天工作量，收益最大）；
2. 统一契约元组与图；
3. 裁决实验设计矛盾——以 v22 crossover 为准重写 v21 §9；
4. 补 Goguen-Meseguer 与 dispute/escalation；
5. 跑一个**单集群 2×2 序列可行性 pilot**：目的不是检验 P1，而是验证 reset 哨兵可达成、监测覆盖率 γ 可达、配对回放可实施——这正是 §10.2 承诺的预注册链上最便宜的第一步，也能直接回应"条件合取太贵所以不可测"的自我预警。
