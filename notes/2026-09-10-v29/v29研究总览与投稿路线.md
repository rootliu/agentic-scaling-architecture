# 从架构论证到可执行数据契约

v29 最值得强化的贡献，是将 Data Wiki、Theme Wiki 与 5W1H+Which Intermediate Relation 转成可执行的数据使用边界：候选检索决定值得读什么，可信策略决定允许读什么，执行期重验证决定此刻还能否读，证据绑定决定最终报告能证明什么。Skill–Harness–Scaffold 继续提供责任框架，P1 继续提供能力与容量的实验问题。这两者不能替代数据契约本身的实证评估。

当前版本已经具备可检查的契约参考实现、有限合成验证、原文核实的近期相关工作，以及比 v28 更一致的测量规则。它仍不是已经达到顶会主会实证要求的完成稿：自然任务效果、完整运行时、真实并发与总成本测量都尚缺失。增加形式化符号、引用或合成测试数量不能消除这些缺口。

## 思想演进与保留边界

7 月 1 日修订的 「06-数据平面四组成架构」 将功能接口与 Raw–Index–Theme 存储分层分开。7 月 10 日的 「2026-07-10」 又强调 allowed 与 intended-now 的差别，以及观测证据与执行正确性的差别。两条线共同说明：数据可被发现与数据可被使用是不同问题；文档被读取与业务答案正确也是不同问题。

7 月 17 日的 「17-DataWiki-ThemeWiki-IR中间关系层」 是目前最清楚的原创设计来源。Data Wiki 面向来源语义，Theme Wiki 面向产出规范，IR 声明两者之间的关系。5W1H 为时效、访问域、拥有者、业务语义、整合理由、物理访问提供可审查字段；Which 补充时间、血缘及跨源关系。贡献不在于这些问题词本身，而在于它们能否共同约束真实访问、变更与证据交付。

「2026-07-撞车月综述与边界重划」 已承认“harness 是系统扩展核心”与“结构化使验证局部化”不能再作为独有贡献。8 月 22 日的 「2026-08-22-今日笔记证据审计与论文改进清单」 进一步收回摘要的普遍充分性及 IR 是唯一耦合点等过强说法。这些收缩是 v29 的基础，不应为了增强论文声势而重新加入。

「12-Skill作为可训练激活层-双子目标Reward」 的可取部分是结果与过程分开评价，但“Skill 必须由模型生成”并非必要条件。过程指标也不能自动证明真实因果归因。「研究原则-情景记忆与WhatIf-HowAbout双引擎」 可作为研究提问方式，但反事实情景生成不等于已经识别因果效应。v29 的确认实验因此优先固定模型与适配器，避免同时引入训练、检索、调度多重改动。

## 技术增量

### 从描述字段到执行谓词

Data Wiki 记录 `source_id / snapshot / digest / schema / policy / operations`。Theme 记录必需字段、单位、期间、证据要求和验证器版本。IR 将它们连接起来。一次请求解析后得到执行票据，绑定来源、主题、身份、策略 epoch 与预算。票据不是一个普通 JSON 就能具备不可伪造性；实际平台必须由可信边界保管或加密绑定。

最小反例是两个列名相同、业务单位或会计期间不同的表：它们的 join 可以在 SQL 类型上合法，却在业务意义上无效。再加入排队期间权限撤销，便能暴露准入时检查与执行时检查的差别。这是比抽象企业架构图更容易被复核的技术问题。

| 维度 | 必需的执行约束 | 独立故障 |
|---|---|---|
| When | 业务期间、有效期、执行时刻 | 队列等待后过期 |
| Where | 读入与交付的域边界 | 内部证据进入公开输出 |
| Who | 可信身份与当前授权 | 准入后撤权 |
| What | 单位、业务口径、实体范围 | 相同字段名代表不同指标 |
| Why | 经批准的整合理由标识 | 模型自行编造 join 理由 |
| How | 允许操作与实际访问方式 | 将 read 请求替换为 write |
| Which | 关系、键、基数、血缘、版本 | 错关系或错快照关联 |

参考模型只实现该表的简化字段检查，不实现多源语义 join，也不验证自然语言解释真假。明确这一边界，才能避免把原型包装成完整系统。

### 撤销与执行的时间语义

检查与读取必须相对于源和策略更新具有共同线性化点。单机参考实现用锁表达这个前提。若是跨网络读取，适配器必须实现事务、租约或 epoch fencing 等一致性机制，仅在发送请求前检查一次不够。

读取若在撤权前线性化，已泄露到模型上下文的字节不能被后来撤权自动收回。因此，报告发布是新的授权事件，必须再次检查。v29 只给条件式安全论证：可信描述、完整中介、原子检查读取与真实字节证据全部成立，成功读取才满足声明谓词。它不是对平台安全的无条件证明。

### 变更局部性

显式记录来源、schema、策略、算子、IR、Theme、产物之间的依赖。变更后使所有可达依赖失效，未受影响的对象才可能保持有效。算法是标准依赖图遍历；新意只能来自这些依赖的契约语义及其减少实际变更传播的效果。

“图外决策不变”需要所有依赖都被捕获，且验证器只读取声明的不可变依赖。隐藏视图、共享 prompt、模型替换、mutable latest 别名都会破坏前提。参考实现采取保守全局 epoch，没有实现细粒度依赖优化，不能宣称其重验证成本已降低。

## 已执行证据及其外推边界

`artifact_v29` 对一个有效收入记录施加十个二值故障维度，穷举 1,024 种组合。结果：有效组合1个通过，无效组合1,023个拒绝，与独立定义的有限域 oracle 无分歧。另有5个生命周期检查通过：准入后撤权、同名版本替换字节、等待中过期、稳定重复读、兼容变更后的重验证。

原始逐例 CSV 与 JSON 汇总包含解释器版本和源码哈希。测试域与实现是在本次修订共同设计的，不是预注册实验，也没有独立研究组复现。组合数量不是样本量意义上的统计效力；故障占比不是企业真实分布；零分歧不能作为真实环境失效率的置信上界。

P1、P15、P16、P17 均仍无本研究的确认性实验结果。参考实现只是让部分声明成为可执行、可审查的对象。

## v28 的方法学修正

1. **四态裁决互斥**：测量或校准不足先判 inconclusive；已充分测量而明确违反义务判 conditional-engineering；义务区间跨阈值仍为 inconclusive；全部义务通过后，才对 P1 的效果与成本判 supported/falsified/inconclusive。
2. **阈值归属清楚**：10% 的交互界与5个百分点的非劣界改为示例，实际必须由具体业务决策给出。不能用 pilot 方差倒推可容忍退化。
3. **删除错误功效示例**：均值 design effect 不能直接推出 period-level p95 的所需集群数。改为保留尾分布、超时、相关性、carryover 和丢失机制的模拟功效设计。
4. **修正“完整中介率非零”措辞**：应检查违规率及其区间，而非中介覆盖本身非零。
5. **形式化支持集明确**：分区充分性命题需每个声明 source–query 组合具有正概率，否则零条件熵只能支持联合分布上的 almost-sure 结论。
6. **承认协议仍需实例化**：未填决策阈值与样本量的协议是模板，不是别人可直接执行的完整 preregistration。

## 达到主会证据要求的最短路线

先聚焦数据契约，不同时承担模型训练、企业组织调查和大规模运行时全部贡献。选择至少两个具有独立来源的报告集合，按来源、模板血缘和时间切分开发集与测试集，人工记录合法实体、单位、期间、关系和证据位置。数量由 pilot 和决策界的功效分析决定，不用任意题数装作足够。

固定检索候选、工具、上下文预算与模型，比较 prose-only catalog 与 enforced contract，隔离强制执行的作用。另做排序发现/操作导航与有无契约的因子对照，加入已调优 dense、BM25、hybrid、直接原文读取。对每个维度做有针对性的失效或移除实验，并包括自然错误与合成注入两类。

主指标是所有必需字段正确且证据有效的任务比例、未授权或过期释放率、合法任务误拒率。拒绝一切可以很“安全”但没有用，因此质量、覆盖、拒答必须一起报告。引用存在不能证明蕴含；数值应有单位规范化与操作数检查，必要时对语义蕴含 judge 做人工校准。

成本包括构建、增量维护、重验证、原文回读、在线 token/时延和人工。按复用次数画生命周期成本曲线。随后才将相同契约接入两个可替换运行后端，做能力×容量实验；始终记录实际路由、超时、失败恢复与整个会话树资源。未完成这些工作前，v29 应保留“研究预印本”定位。
